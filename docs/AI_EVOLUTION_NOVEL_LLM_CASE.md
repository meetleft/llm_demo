# 案例：Novel LLM 从 Qwen 微调到 MCP 智能体

本文将“希萌”知识库中的《AI发展演变与大事件科普演讲提纲》映射到当前项目 `D:/python_work/novel_llm`，作为可运行的 AI 演进案例。

## 1. 项目目标

本项目让一个中文小说助手同时完成简单问答和专业小说创作：问答使用 Qwen 基础模型，小说任务结合 LoRA、世界观、人物、时间线、伏笔和章节记忆。

## 2. AI 演进阶段与当前项目

| 演进阶段 | 当前项目实现 | 对应能力 |
| --- | --- | --- |
| 基础模型 | `Qwen2.5-1.5B-Instruct` | 通用中文理解与生成 |
| 领域适配 | `outputs/qwen25-1.5b-novel-lora` | 小说语气、章节续写、创作格式 |
| 推理服务 | `scripts/langchain_agent.py` 的 `LocalQwenRuntime` | 加载模型、切换 LoRA、控制生成参数 |
| Agent 编排 | `NovelLangChainAgent` | 问答、规划、写作、编辑、记忆提取的流程编排 |
| 长期记忆 / RAG | `NovelMemoryStore` | 世界观、人物、时间线、伏笔和章节摘要 |
| Web UI | `app/codex_ui.py` | 浏览器聊天、资料编辑、章节查看、工具调用 |
| MCP | `scripts/novel_memory_mcp.py` 与 MCP Client | 通过标准协议暴露查询工具并扩展外部知识库 |

## 3. 小说续写案例

用户输入：

> 请继续写龙拜剑仙为师后的下一章，保持前文设定，并检查未回收伏笔。

系统链路：

1. 页面将问题交给 `NovelLangChainAgent`。
2. Qwen 先做语义路由，判断是否需要项目资料，不依赖关键词。
3. MCP Client 在白名单内调用 `get_novel_context` 或 `get_unresolved_foreshadowing`。
4. `NovelMemoryStore` 读取世界观、人物、时间线和最近章节。
5. 基础模型生成创作计划。
6. 小说 LoRA 生成章节草稿。
7. 基础模型进行终稿编辑并检查连续性。
8. 用户确认保存后，章节和摘要、人物变化、时间线、伏笔才写入长期记忆。

这体现了 AI 从“生成文本”演进到“理解目标、检索资料、调用工具、执行多步任务”。

## 4. 基于记忆的问答案例

用户输入：

> 龙是谁？他之前经历了什么？

语义路由会判断该问题依赖项目角色和章节事实，调用 MCP 查询小说记忆，再让基础模型依据返回资料回答。若资料中没有记录，应明确回答“项目记忆中没有找到相关记录”，而不是凭空补全。

这里对应知识库演进中的 RAG：模型负责理解和表达，知识库负责提供可追溯事实。

## 5. 不依赖记忆的创作案例

用户输入：

> 写一段雨夜相遇的东方奇幻场景，不引用本项目人物。

模型可以判断不需要查询 MCP，直接使用 LoRA 创作流程。这样既保留创作自由，也避免把无关设定带入。

## 6. MCP 工具边界

当前本地 MCP 服务为只读白名单，提供：

- `get_novel_context`：读取综合上下文。
- `list_chapters`：列出章节。
- `search_chapters`：搜索章节片段。
- `get_character`：查询人物档案。
- `get_unresolved_foreshadowing`：查询未回收伏笔。

模型不能直接执行任意命令，只能输出结构化调用计划，Python 再校验工具名、参数和调用次数。工具结果标记为外部资料，不会覆盖系统规则，也不会自动写入记忆。

## 7. 工程原则与后续演进

1. LoRA 负责写作风格，记忆和 MCP 负责事实与工具。
2. 需要项目事实时先检索再生成，降低幻觉。
3. 1.5B 模型采用结构化路由和 Python 校验，不开放无限制自由 ReAct。
4. 写入章节和长期记忆必须显式确认。
5. 后续可加入希萌知识库的只读搜索、引用来源展示、MCP 审计日志、超时重试和章节向量索引。
